portal v0.8.1 fixes a bug in v0.8.0's brand-new `portal upgrade`, found by
using it.

## Fixed: `upgrade` compared the wrong binary

`portal upgrade` decided whether an update was needed by looking at the
version of the **process you invoked**, not the version of the binary at
`~/.local/bin/portal` — the one the login daemon actually executes.

Those are the same file in the common case, so `portal upgrade` from an
installed copy behaved correctly. But running a freshly built `./portal`
from a source checkout against a stale install reported `up to date` and
exited without touching anything, leaving the daemon on old code.

`upgrade` now asks the installed binary for its own version and compares
that. If the installed binary is missing or refuses to run, it falls back to
the running process's version and proceeds — a broken install must not block
the download that would repair it.

If you are on v0.8.0 and `portal upgrade` claims you are current, this is
why; `portal upgrade --force` gets you here.
