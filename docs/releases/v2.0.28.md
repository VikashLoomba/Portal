# Portal v2.0.28

Portal v2.0.28 replaces the Rust/AppKit desktop host with one native SwiftUI
application while retaining the existing Rust transport, daemon, CLI, update,
security, and remote-agent behavior.

## One application, one executable

`Portal.app/Contents/MacOS/Portal` is now the only compiled macOS executable.
The same signed process runs in distinct GUI, CLI, daemon, credential-prompt,
and update-helper modes. The daemon remains an independent process, so closing
or quitting the SwiftUI application does not stop forwarding, clipboard sync,
notifications, credential service, or remote agents.

The installed `~/.local/bin/portal` command points to a small launcher inside
the app bundle. It preserves arguments, standard input/output, and exit status,
then executes the application in CLI mode. Existing standalone executable and
launchd invocation shapes remain accepted during upgrades.

## Native SwiftUI interface

- Native menu-bar presentation with live green, yellow, red, and disabled
  connection indicators.
- A management window for boxes, active forwards, atomic always-forward
  allowlists, feature gates, logs, and signed updates.
- A native secure credential approval prompt, including remembered-item,
  forget, deny, and empty-secret fail-closed behavior.
- Event-driven state updates through a reconnecting `AsyncStream`; the UI does
  not poll and never owns daemon state.
- Keyboard-accessible application and View menus, native focus behavior, and
  explicit accessibility labels for stateful controls.

## Rust through BoltFFI

Rust remains responsible for CLI/domain behavior, local API transport, SSH,
forwarding, configuration, clipboard and credential policy, updates,
installation, rollback, and both embedded Linux `portald` agents. A pinned
BoltFFI 0.30.1 static XCFramework links this logic into the Swift executable.
The public Swift boundary is value-oriented and ownerless and compiles under
Swift 6 complete strict concurrency.

## Packaging and release integrity

The release pipeline verifies:

- exactly one Mach-O in the app bundle;
- a macOS 13 deployment target;
- both embedded Linux-agent architectures and the shared source SHA;
- CLI launcher behavior and all executable process modes;
- Developer ID signatures, hardened runtime, Gatekeeper, notarization, and
  stapling;
- minisign verification for app, DMG, and compatibility artifacts;
- signed local installation, healthy LaunchAgents, remote convergence, and a
  real post-swap failure with byte-for-byte rollback.

Pre-app v2 and v1 upgraders continue receiving a signed compatibility copy of
the same Portal executable, which completes migration to `Portal.app` without
losing the daemon or CLI path.
