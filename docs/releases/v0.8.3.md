portal v0.8.3 closes a credential-disclosure bug in `portal keychain askpass`.
**If you use the sudo bridge, upgrade and rotate the password you have
remembered.**

## Fixed: askpass served a live secret to anyone who ran it

`portal keychain askpass` is the `SUDO_ASKPASS` helper sudo calls for you.
Because sudo passes its prompt as ordinary arguments, v1 deliberately treated
*every* argument as opaque prompt text — including `--help`.

The consequence: running `portal keychain askpass --help` expecting usage
text instead fired a real credential request at the Mac. Approve it out of
habit and askpass does what the askpass protocol requires — writes the
approved secret to **stdout**. When the caller is a coding agent, that stdout
is the agent's context window. This happened, with a real password.

That is the exact outcome the feature exists to prevent: the whole point of
`portal keychain` is that a secret never enters an agent's context,
transcript, argv, or logs.

## What changed

- **A lone `help`/`-h`/`--help` prints help and never requests.** sudo's
  prompt is human text like `[sudo] password for you:`, so giving up
  `--help` as literal prompt text costs nothing. A help token *alongside*
  other arguments is still prompt text.
- **askpass refuses unless a real askpass consumer invoked it** — `sudo`,
  `sudoedit`, `sudo-rs`, or `ssh` — and fails closed when the parent cannot
  be determined. The refusal happens *before* any request, so you are never
  asked to approve a disclosure bound for someone's transcript. Wiring the
  helper into another askpass-protocol consumer is still possible with
  `PORTAL_ASKPASS_ALLOW_ANY=1`.

Nothing changes for normal use: `sudo <command>` over ssh works exactly as
before, because the shim `exec`s portald and the parent stays sudo.

## Honest scope

This guard prevents **accidents, not attackers**. A hostile same-uid process
on the dev box can present whatever parent it likes — an adversary the cred
threat model has always excluded and still does. What it removes is the far
likelier failure: a person or an agent probing a CLI and being handed a
password for their trouble.

To exercise the credential path deliberately, use the mode built for it:

```sh
portal keychain run --label "test" --env PW -- sh -c 'echo "len=${#PW}"'
```
