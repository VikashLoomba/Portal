portal v0.8.0 adds **`portal upgrade`**. Updating the Mac side no longer
means finding the release page and re-running the installer.

## New: `portal upgrade`

```sh
portal upgrade          # install the newest release and reload the daemon
portal upgrade --check  # report whether a newer release exists; download nothing
portal upgrade --force  # re-install the published release even if current
```

Until now the only documented way to update was to download
`portal-darwin-arm64` by hand and run `install` again — which is spelled as
*installation*, not as an upgrade, and nothing ever told you a newer release
existed. Meanwhile the dev-box half of portal has always upgraded itself:
the agent and clipboard shims re-converge on the next daemon reconnect. The
Mac side now has a matching path.

## Safety: verify before replacing

The order is the point. `upgrade` stages the download beside the installed
binary, **executes it once and requires it to report the expected release
tag**, and only then swaps it in with an atomic rename — which is safe while
the daemon is executing the old inode, and cannot leave a half-written binary
the way a truncating copy can.

Anything that goes wrong leaves your working binary exactly where it was: a
truncated or empty asset, a wrong-architecture file that will not execute, or
a binary that runs but reports a version other than the release claimed. If
the swap succeeds and only the daemon reload fails, the message says the
upgrade landed and points at `portal restart`, rather than implying it did
not.

## Details

- A build made from a git checkout (`v0.7.0-3-gabc1234`) already sits *after*
  its base tag, so it is reported as current instead of being moved backwards.
  `--force` overrides that.
- Releases publish an Apple Silicon binary only, so any other host is refused
  before a single network request, with a pointer to building from source.
- Nothing on the dev box changes — the agent and shims keep converging on
  their own.
- No new module dependencies; the release lookup is stdlib `net/http` against
  the GitHub releases API.
