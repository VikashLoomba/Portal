# Portal v2.0.29

Portal v2.0.29 adds native file and folder uploads from the macOS app to
connected remote boxes.

## Drag-and-drop uploads

Each enabled box card now includes an upload target. Drag files or folders from
Finder onto it, or click the target to choose multiple items with the native
macOS open panel. Portal uploads each selected item beneath
`~/tmp/portal/<item>` by default and reports in-progress, successful, and failed
transfers directly on the box card.

Large folders are written as a streaming tar archive: Portal does not buffer
the complete archive in memory or write a temporary local archive. The daemon
forwards the stream over a dedicated channel on the box's existing SSH
connection, leaving the long-lived agent and forwarded services independent.

## Remote destination picker

The destination control opens a native SwiftUI remote-folder browser. It can:

- navigate from the remote home directory through child and parent folders;
- open an absolute or `~/` path directly;
- create a destination folder; and
- select a folder for subsequent uploads to that box.

Remote path values are shell-quoted without evaluating user input, while `~`
expands only to the authenticated remote user's home directory.

## Transfer protocol and validation

The owner-only local API now uses a two-phase upload handshake: the daemon
opens and acknowledges the remote extraction channel before the app sends any
archive bytes. Upload roots must be regular files, directories, or symbolic
links, and duplicate top-level names are rejected rather than silently
colliding. Directory listings use NUL-delimited fields so whitespace and
newlines remain unambiguous.
